# 0.2.2 修复候选验证记录

验证日期：2026-10-24。针对 HoKit 手机端重签后出现的代码签名验证失败，调整随包可执行文件的名称和调用方式。当前为本地修复候选，尚未替换 GitHub 的 0.2.1 下载。

## 本次通过

| 项目 | 方法与结果 |
| --- | --- |
| 问题定位 | 旧版 OpenHarmony C++ 签名器会跳过路径中没有点号的文件。本地 HoKit 桌面版 1.8.7 附带的手机端 1.8.0 原生签名库存在同一逻辑；详见[签名兼容性说明](SIGNING-COMPATIBILITY.md) |
| 构建 | macOS Apple Silicon + DevEco Command Line Tools 26，完整 release 构建通过 |
| 自动化回归 | 22 项 Node/ArkTS 测试和 6 项 Python 包校验测试通过，无跳过；包含真实上游搜索索引，以及新启动脚本的命令名、参数传递和失败路径测试 |
| HAP 结构 | ZIP 完整性、API 26 / 2in1、版本 0.2.2 / 1001002、9 个可执行文件、9 个启动脚本的可执行位及 119 个关键运行时文件校验通过 |
| 代码签名 | 使用既有本地签名配置构建后，SDK 的 `verify-app` 验证成功；103 个原生文件均被验证，包含全部 9 个 `.bin` 程序。这是 SDK 签名测试，不代表已通过用户手机上的 HoKit 重签 |
| 二进制一致性 | 与 0.2.1 对比，103 个原生文件内容完全一致；9 个程序只改包内文件名，权限节和共享库不变 |
| 模拟器命令执行 | HarmonyOS 6.1.1 / API 24 PC 模拟器，在应用沙箱中执行 Node、Python（含 SSL、SQLite 导入）、ripgrep、Git 均成功；本地 Git 仓库初始化和 `ls-remote` 成功，覆盖 `git-upload-pack` helper 调用 |
| 最终包启动 | 移除临时诊断代码，使用同一源码和运行时资源构建 API 24 模拟器专用包；覆盖安装成功，应用启动并报告 Kimi 服务就绪 |

命令测试使用临时诊断入口，最终交付 HAP 不包含该入口。模拟器专用包只用于验证，不作为公开附件；提供给使用者的修复包仍要求 API 26 鸿蒙 PC。
